# NEXT_STEPS: Firebase Authentication Setup

This document outlines the additional steps required to complete the Firebase authentication setup for the Flutbook app.

## Prerequisites

- A Google account with access to the Firebase Console
- Flutter project with FlutterFire CLI installed
- Access to platform-specific configuration files (iOS: `GoogleService-Info.plist`, Android: `google-services.json`)

## Step 1: Configure Your Firebase Project

### 1.1 Create or Select a Firebase Project
1. Go to the [Firebase Console](https://console.firebase.google.com/)
2. Create a new project or select an existing one
3. Follow the setup steps to enable Firebase for your project

### 1.2 Add Your App to the Project
For each platform you're targeting:

**For Android:**
1. Click "Android" in the project setup page
2. Enter the Android package name (e.g., `com.example.flutbook`)
3. Download the `google-services.json` file
4. Place it in the `android/app/` directory of your Flutter project

**For iOS:**
1. Click "iOS" in the project setup page
2. Enter the iOS bundle ID (e.g., `com.example.flutbook`)
3. Download the `GoogleService-Info.plist` file
4. Add it to your Xcode project (or place in `ios/Runner/` directory)

**For Web:**
1. Click "Web" in the project setup page
2. Enter your web app nickname
3. This configuration will be included in the Firebase options

## Step 2: Install FlutterFire CLI

If you don't have FlutterFire CLI installed, run:

```bash
dart pub global activate flutterfire_cli
```

## Step 3: Configure Firebase for Your Flutter App

Run the FlutterFire configure command in your Flutter project directory:

```bash
flutterfire configure
```

This command will:
- Ask you to select the Firebase project you created
- Ask which platforms you're configuring (Android, iOS, Web)
- Generate the `lib/firebase_options.dart` file with your project configuration
- Update the `pubspec.yaml` file if necessary

## Step 4: Update Firebase Configuration

Replace the placeholder `firebase_options.dart` file with the one generated by `flutterfire configure`. The generated file will contain your actual project configuration.

## Step 5: Enable Authentication Methods

In the Firebase Console:
1. Go to the Authentication section
2. Click on the "Sign-in method" tab
3. Enable the sign-in methods you want to support:
   - **Email/Password**: Enable for traditional email/password authentication
   - **Google**: Enable for Google sign-in (requires OAuth client setup)
   - **Anonymous**: Enable for guest/anonymous access

### For Google Sign-In:
1. In the Google Cloud Console, create OAuth consent screen if not already done
2. Create OAuth 2.0 credentials for your project
3. Add your domain to authorized domains in Firebase Console
4. Add the OAuth client ID to your Firebase Authentication configuration

## Step 6: Platform-Specific Configuration

### Android Configuration
Ensure the following permissions are in your `android/app/src/main/AndroidManifest.xml`:
```xml
<uses-permission android:name="android.permission.INTERNET" />
```

### iOS Configuration
In your `ios/Runner/Info.plist`, add the URL schemes for Google Sign-In:
```xml
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleURLName</key>
        <string>REVERSED_CLIENT_ID</string>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>YOUR_REVERSED_CLIENT_ID</string>
        </array>
    </dict>
</array>
```

### Web Configuration
For web deployment, ensure you update the authorized domains in the Firebase Console with your domain.

## Step 9: Security Rules Configuration

### Firestore Security Rules
If using Firestore for audiobook data synchronization, update your security rules in the Firebase Console:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Allow users to access their own data
    match /users/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
    // Add other collections as needed for your audiobook data
  }
}
```

### Storage Security Rules (if using Firebase Storage)
```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{userId}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

## Troubleshooting Common Issues

### Issue: `No Firebase App '[DEFAULT]' has been created`
**Solution**: Ensure Firebase is initialized in your `main` function before any Firebase services are used.

### Issue: Google Sign-In not working on mobile
**Solution**: 
- Check that SHA-1 fingerprints are correctly added to Firebase Console for Android
- Verify bundle ID and URL schemes for iOS
- Ensure the Google Sign-In SDK is properly configured

### Issue: Method not implemented errors
**Solution**: This often occurs when platform-specific implementation is missing. Make sure platform-specific dependencies and configurations are set up correctly.

## Security Best Practices

1. Never expose sensitive API keys in client code
2. Use Firebase Security Rules to control data access
3. Implement proper user permission checks
4. Use Firebase Authentication's built-in security features
5. Regularly review and update your security rules
6. Monitor authentication events for suspicious activity
